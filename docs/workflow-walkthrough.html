AI governance lifecycle

Six-step offline walkthrough · illustrative fictional use case · refresh to replay

01 · AI use-case intake

Capture purpose, data, users, deployment, and oversight.

Artifact: intake form + registry entry

cd ai-use-case-intake && python3 triage.py --demo

02 · Risk classification

Apply a transparent, reviewable EU AI Act triage rule set.

Artifact: tier, rationale, flags, obligations

cd eu-ai-act-risk-classifier && python3 classify.py --demo

03 · Evaluation

Test safety, bias, calibration, and controls before approval.

Artifact: Laya report + evaluation evidence

cd laya-governance-experiments && python3 analyze.py

04 · Approval decision

Record owner, reviewer, conditions, and expiry in the registry.

Artifact: lineage report + approval record

cd model-registry && python3 seed.py --reset

05 · Monitoring

Track controls, actions, due dates, and incidents over time.

Artifact: dashboard.html + audit log

cd governance-dashboard && python3 build.py --demo

06 · Incident response

Contain, investigate, document, remediate, and re-test.

Artifact: incident runbook + deconstruction

read ai-governance-playbook/templates/incident-runbook.md
